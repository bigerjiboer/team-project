# 团队协作项目

> 本仓库是团队的**项目文档中心 + 文件发布中心**。成员在此共享文档、发布文件，并通过「提交 → 审核 → 入库」的流程互相检查质量。

## 这个仓库怎么用

本仓库承担三类职责，分别对应不同的工作区：

| 你要做什么 | 放到哪里 | 怎么做 |
| --- | --- | --- |
| 记录项目信息、进度、约定 | `README.md`、`docs/` | 直接编辑后提 Pull Request |
| 发布一份文件（报告/代码/资料/模板） | `docs/` 或 `assets/`（按类型建子目录） | 推送分支 → 提 Pull Request → 等人审核 |
| 发布大型/二进制文件（>10MB） | GitHub Releases | 合并 PR 后由管理员创建 Release |
| 提出任务 / 讨论问题 | GitHub Issues | 新建 Issue 并指派负责人 |

## 快速上手（给新成员）

```bash
# 1. 克隆仓库
git clone https://github.com/bigerjiboer/team-project.git
cd team-project

# 2. 每次开工前先同步最新代码
git pull

# 3. 为你的改动新建一个分支（禁止直接改 main）
git checkout -b docs/你的名字-要做的内容
# 例如: git checkout -b docs/xiaoming-新增周报模板

# 4. 改完提交并推送
git add .
git commit -m "docs: 新增周报模板"
git push -u origin docs/你的名字-要做的内容
```

推送后打开 GitHub，仓库页面会提示你 **Compare & pull request** —— 点击它发起 Pull Request，等待审核人检查通过后合并。

## 发布文件 / 检查文件的流程（核心）

```
成员写内容 ──► 推送到自己的分支 ──► 发起 Pull Request
                                        │
                                        ▼
                           负责人 Review（检查文件内容）
                                        │
              ┌─────────────────────────┼─────────────────────────┐
              ▼                         ▼                         ▼
       有问题：留言 / 打回           没问题：Approve             修改后再提
              │                         │                         │
              └────────── 作者修改 ─────┴──────► 合并进 main ◄─────┘
```

**一句话总结：任何进入 `main` 的内容都必须先经过一次 Pull Request 审核。** 这样每次改动都有记录、可回溯、可讨论。详细规则见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 目录结构约定

```
team-project/
├── README.md          # 项目首页文档（你正在看的）
├── CONTRIBUTING.md    # 协作规范：分支、提交流程、审核要求
├── docs/              # 项目文档（方案、周报、说明等）
│   ├── 01-项目说明/    # 按主题分子目录，不要全部堆在根目录
│   ├── 02-模板/        # 各类可复用模板
│   └── ...
├── assets/            # 需要归档共享的资料文件（图片、表格等）
└── .github/           # PR 模板等仓库配置（一般不用动）
```

> 没有现成分类就先按 `docs/主题名/文件名` 的规律新建目录，保持整洁即可。
